>Striving to be better, oft we mar what's well. - Shakespeare, King Lear

Just to make it clear, "good enough" software does not imply sloppy or poorly written code.

What it actually means is that the software successfully meets the user's needs/requirements and basic performance, security and privacy standards.

Let the user decide whether your software is good enough or not by meeting their needs/requirements.

Make a good enough software today then use feedback and such to improve it rather than trying to come up with the perfect software with lots of features and bells and whistles which would take longer. People would rather use a software with rough edges today rather than wait a whole year or something for the perfect software.
## Know When to Stop
Don't spoil a perfectly good software by over-embellishment and over-refinement. Let your code stand for a while rather than trying to perfect it because it will never be perfect.
